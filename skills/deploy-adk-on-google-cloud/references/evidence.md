## What was live, mocked and unimplemented

The [September 13 live report](https://github.com/RuslanKhis/agentic-engineering-adk-gcp/blob/c909d7e5d285ae582abb3899bbe162fa55f075dd/chapter-03-deploying-on-gcp/audit/LIVE-20260913.md) establishes Runtime's functional results. The September 14 follow-up closes both Cloud Run browser paths, GKE routing/recall/direct recovery, the Run reader proxy and rebuilt custom-container telemetry behaviour. It records 37 Run and 48 GKE **offline** tests passing; those 85 checks are not 85 live service calls. Runtime's preceding selected suite had 28 tests. Historical dependency environments were reused in the follow-up.

The [initial offline report](https://github.com/RuslanKhis/agentic-engineering-adk-gcp/blob/c909d7e5d285ae582abb3899bbe162fa55f075dd/chapter-03-deploying-on-gcp/audit/REPORT.md) includes actual SDK CLI/HTTP/database components with replaced cloud/model boundaries. Its earlier cloud-blocked status is superseded only where later reports provide live evidence.

External session/artefact durability, authenticated user-to-session binding, dedicated least-privilege production build identities, IAP/application authentication, Secret Manager integration, distributed locking, immutable promotion/rollback, strict telemetry/logging policy and in-process model/tool budgets are **production principles**, not features proved by this lab. The skill instructs an adopting agent to implement and validate the relevant requirements, rather than claiming the chapter already did so. Source: [revised chapter](https://github.com/RuslanKhis/agentic-engineering-adk-gcp/blob/c909d7e5d285ae582abb3899bbe162fa55f075dd/chapter-03-deploying-on-gcp/manuscript/chapter-03-revised.md).

Public cleanup, repeat cleanup and independent checks passed within recorded visibility. Shared provider buckets, build history/logs, enabled APIs and retention remained. No absolute claim of physical erasure, invisible Autopilot backing-resource inspection or zero future charges follows from those observations.

## Provider contracts

The installed ADK 2.8.0 command help was reopened during skill creation. Check the target's installed version before applying a command. Current official guidance can supplement, but not silently override, the pinned contract: [ADK Cloud Run deployment](https://google.github.io/adk-docs/deploy/cloud-run/), [Cloud Run container contract](https://docs.cloud.google.com/run/docs/container-contract) and [GKE workload identity](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/workload-identity). These provider links are optional reference material, not required dependencies of the offline helper.

The missing-prerequisites forward test also exposed a consequential native Runtime detail. Inspection of installed ADK 2.8.0 `google/adk/cli/cli_deploy.py` showed `agent_engines.update` failure triggers `agent_engines.delete` only when the runtime was newly created by that function. The skill now requires explicit approval of that conditional failure cleanup or a different reviewed execution path. This branch was source-inspected, not run live or exercised as a deletion test. Installed CLI help also documents replacement of existing `--temp_folder` contents; use fresh owned generation directories.
