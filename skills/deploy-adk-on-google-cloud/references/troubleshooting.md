# Diagnose before retrying or broadening access

Use this when a deployment, browser check or cleanup fails. Start with the exact stage, target, deployed version, original request/operation ID and saved response. Read the selected mode's reference for its implementation contract. Bound diagnostic reads and preserve the cleanup reserve from [lifecycle.md](lifecycle.md).

The table distils observed chapter failures and source-tested guards. A matching symptom suggests a check, not proof of the same cause. Do not generalise one accepted identity, controller actor or timing tolerance to another project or SDK version.

| Symptom | Check first | Safe next step and evidence required |
| --- | --- | --- |
| Project lookup denied after changing accounts/projects | Explicit operator account and target, CLI versus ADC, quota project, IAM visibility, billing and enabled APIs separately | Keep state unknown until the intended lookup succeeds. Root `.env`, console selection and nested `.env` can disagree. A new project needs fresh state and recreated resources, never an old runtime ID. Do not dump key values or enable APIs as a diagnostic read. |
| Healthy service, model request fails | Actual runtime identity, model/backend/project/location, installed client arguments, deployed environment and effective inference permission | Verify these independently of the deployer's successful build. Host region is not necessarily inference location. Fix the consumer's configuration, then verify a new revision/managed update under approved scope. |
| GKE authentication, image pull or readiness fails | Separate operator/plugin/private-kubeconfig access, node registry-read identity, and actual listener/probe/Service ports | Match the failure to its stage. Runtime KSA model permissions cannot fix an image pull. Verify the digest exists and the probe route is real; avoid paid model calls in probes. These checks follow the implemented boundaries, not a claim every failure was reproduced live. |
| Build cannot read source or push an image | Regional actual build identity, source generation, repository scope and terminal build record | Do not guess a Compute account or grant Editor. Derive the narrow missing permission, prepare its exact scope, then obtain missing approval. IAM policy presence is not proof of effective access; observed propagation was a hypothesis. |
| Native deploy exits zero but prints a source rejection | Exact service state, matching accepted regional builds, saved upload generation and provider error | Treat deployment as failed/uncertain. Only proven rejection with no accepted work qualifies for the chapter's narrow exact-generation recovery. An accepted timeout stays pending; do not resubmit blindly. |
| New service-account create succeeds, immediate GET says absent | Accepted create receipt, exact project/email/UID and known provider visibility lag | Use a bounded read-only recheck, not another create. The lab used two delayed reads; its particular delays are not a universal timing guarantee. Denied reads are still unknown. |
| `/list-apps` works, requested session/app route fails | Discovered package app ID versus internal agent name; direct state-dictionary body; installed HTTP schema; unique test IDs | Correct the test request offline. Reused IDs may test stale state; a nested `state` object is not the baseline create-session contract. Delete only the synthetic sessions owned by the test. |
| Cloud Run browser 401 | Caller type, token audience/client, actual invocation permission and supported token acquisition | The historical custom OAuth CLI-token path failed while existing standard ADC worked. Adapt the verified caller path; do not make the service public or log tokens. This does not prove every 401 has that cause. |
| Local TLS verification fails before an HTTP response | Actual executable and CA store used by that interpreter/curl environment | Repair the documented trust store and retain certificate verification. Shell environments can select different curl/CA installations. This is prerequisite troubleshooting advice from the repository, not a new live integration result. |
| HTML loads but browser JavaScript/module requests return 403 | Actual Host/Origin, `Forwarded` and `X-Forwarded-*` seen through the transport | Reproduce using the real documented proxy. Preserve exact loopback restrictions and upstream authentication if a bridge is required. CORS wildcards or blanket origin rewriting are not the repair. A test recorder that rewrites Host can itself cause failure. |
| Telemetry opt-out returns 500 in a custom container | Non-root user's actual home directory, ownership/writability and SDK preference path | Create the writable home, rebuild, verify running digest/revision, then repeat the endpoint and browser reload. Same-Pod reload persistence does not prove replacement durability. A native optional-route 404 is a different outcome. |
| Runtime HTTP 200, verifier says no events/tool/answer | Saved response bytes and actual framing/content; transport errors and event error fields; exact session history | The observed response was NDJSON despite an SSE query parameter. Correct the parser against those bytes, rerun it offline, and inspect the existing session before any new model call. Do not fabricate an SSE wrapper to make a fixture pass. |
| Follow-up recalls the fact but verifier demands a tool | Purpose of this turn and the earlier stored event | Recall-only success need not invoke the tool again. Use separate acceptance rules for routing/tool execution and recall; another paid request does not repair an incorrect oracle. |
| Tool result is right, final text promises an action never taken | Exact function result versus final claimed effects | A classification tool does not file a ticket or promise follow-up. Strengthen instructions and assertions around that real contract; preserve contradictions as failures. For consequential tools, also correlate invocation/call/result/final events. |
| Browser shows duplicate bubbles or returns a 502 | Whether the original request reached the server; accepted turns, call IDs and durable effect receipts | Restore input and show actionable feedback. Replay only with proven non-delivery or a tested deduplication contract. The lab verified a disconnected tunnel before dispatch; its proxy 502 restored input without visible error. These are different acceptance results. |
| Runtime wrapper refuses concurrent/repeated work | OS lock, saved target, pending intent, operation ID and SDK failure-cleanup branch | Wait or reconcile the recorded operation within bounds. Releasing a process lock does not resolve a provider-side outcome. Repeating the chapter's wrapper updates the saved runtime; it is not a verification-only command. |
| GKE cleanup refuses a late system-looking object | Original baseline, exact UID/creation time, creator records and reviewed owner/node chain | Preserve refusal until that exact object is proved. Never adopt everything in a provider namespace, refresh the baseline or use a receipt as unlimited authority for descendants. Recheck the full proposed batch before mutation. |
| Deleted service account GET returns 403 | Exact API target and a successful complete project inventory | The historical wildcard-project lookup could return 403 for an absent account. Claim absence only when a complete authorised inventory excludes the recorded email and UID. Denied, truncated or malformed inventories remain unknown. |
| Storage cleanup reports not found, or an empty bucket remains | Exact target-specific provider error, URI encoding, generation and bucket operation | A permission error containing `404` in a path is not absence. Remove only owned generations with preconditions; emptying an owned bucket still requires bucket deletion. Preserve shared buckets and disclose retention. |
| An IAM grant reappears after the journal says it was removed | Current member/role/condition, immutable subject where available, deletion receipt and other actors | Do not delete again automatically. A later matching grant may belong to another actor. Reconcile ownership and approval; preserve unrelated policy changes with conditional updates. |
| Verification budget exhausted during teardown | Fan-out inventory, SDK polling, retries/refusals and independent checks | Pause optional work before the reserve is consumed. Record the original breach honestly and obtain revised scope if needed. The historical 917/600 overrun was a failed constraint, not made compliant by changing a test. |

## Retain enough evidence to fix the verifier offline

Capture a bounded, access-controlled raw response and status metadata before parsing; preserve them on a verification failure until diagnosis is complete. Keep credentials out, use synthetic data, and remove evidence according to its retention policy. The historical Runtime shell helper deleted its temporary response on failure, forcing recovery from the exact existing session. An improved harness should not require another paid request merely to rediscover the bytes.

A parser should distinguish transport failure, non-success HTTP status, provider/application error events, empty/truncated output and a completed semantic failure. Test the framing actually observed: NDJSON, SSE line/block rules and JSON envelopes are not interchangeable. Include field aliases the installed SDK emits and exclude internal thought text from final-answer assertions. Preserve invocation/call IDs when available. State the parser's supported subset; accepting one `data:` JSON per line does not prove arbitrary multiline SSE support.

For a suspected harness failure, compare the saved response and session history with the harness expectation, repair the parser/oracle locally, then rerun on the **same** data. If the response/history cannot establish whether an effect occurred, retain `unknown` or `pending`; absence of an answer on screen is not proof of non-delivery. Use [validation.md](validation.md) for the relevant turn-specific acceptance test.

## What closes an incident

Record the observed symptom, established cause versus hypothesis, exact repaired code/configuration, offline regression result and any newly authorised live observation. A rebuilt container must be the revision serving the successful test. Retain failed acceptance cases alongside passes, including missing visible UI errors and inaccessible resources. Link to [evidence.md](evidence.md) for the historical campaign's scope; do not present a diagnosis recipe as another live verification.
