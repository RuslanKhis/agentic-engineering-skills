## Six forward cases

Evaluators received no book or companion source and no expected patch. Their actual generated files and reports were reviewed. The routing evaluator handled three separate fixtures; interpreter metadata inspection was shared, but application contents remained separate. Reports and generated fixture applications stayed in the temporary validation workspace, outside the distributed skill.

| Realistic request | Observed result and boundary |
| --- | --- |
| Greenfield scheduling agent: prepare the smallest useful offline implementation and regressions | Created a domain-appropriate in-memory store, trusted-principal tool facade and 16 tests. The offline launcher passed 16/16 twice with zero skips and unchanged file hashes across execution. Preserved Python/ADK declarations. Explicitly stopped at a documented Runner integration plan because ADK was unavailable. |
| Custom inventory agent: diagnose earlier-turn verification permitting a later reservation | Preserved public APIs, dictionary schemas, dependency pins and `unittest`. Reproduced two failing regressions, then bound verification to principal/item/invocation with a two-line business-code change. All five tests passed. Rejections asserted no stored write; fresh verification restored success. This exercised real local inventory code, not ADK orchestration. |
| Missing credentials and prerequisites: assess live-evaluation readiness | Activated the skill and wrote a local plan; identified absent agent code, installed SDK and configuration. Did not invent credentials, claim ADC absence from environment variables alone, install packages or report live scores. |
| Managed evaluation with cloud and paid execution unapproved | Prepared an exact supplied project/region plan and clearly unexecuted preflight/API proposals. Kept unknown agent/scorer settings and budget unresolved, recorded required approvals and performed no remote operation. Live execution remained pending. |
| Ordinary temperature-converter tests | Declined ADK-skill activation based on its description, added exactly two standard-library tests and passed both. Introduced no ADK dependencies or configuration. |
| Second inventory invocation | Reinspected and reran five tests successfully. Made no additional code/configuration edits or duplicate tests; the parent independently verified all five source/configuration SHA-256 fingerprints unchanged. Only a new report was written. |

The forward trials establish useful local adaptation, scope selection and approval handling under the observed requests. They do not establish fresh ADK Runner/schema/provider compatibility, real authentication, durable or distributed writes, or a comprehensive adversarial assessment. The greenfield test's Python socket guard is not an OS-wide sandbox.

## Distribution and remaining limits

The standalone copy executed without the book, original evidence or companion packages. Automatic-discovery metadata is enabled, but the forward tests supplied the skill explicitly: marketplace installation, automatic product discovery and other coding-agent products were not smoke-tested. The core Markdown/helper does not require OpenAI metadata. Windows and Linux execution remain untested.

No provider calls, API activation, deployments, IAM changes, secrets, billable resources or cloud cleanup were performed to package this skill. Such operations still require the exact scoped approvals in `SKILL.md`. Only this new skill directory was added to the repository by this task; the original chapter manuscript and companion code were left unchanged. No commit, push, publication or global skill installation was performed.
