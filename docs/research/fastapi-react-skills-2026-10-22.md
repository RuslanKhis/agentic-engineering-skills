# Pin upstream skills, own only the ADK seams

Adopt upstream, version-matched skills as named companions, and write first-party content only where ADK changes the answer. **For the backend, that means FastAPI's own skill, which has shipped inside the `fastapi` wheel since 0.133.1 and installs with `uvx library-skills`, and no third-party FastAPI skill at all**: the two most-installed ones (wshobson at 25.7k installs, Jeffallan at 6.0k) teach patterns the official skill now rejects. For React engineering it means Vercel's `vercel-react-best-practices` with its server rules scoped out, the framework-owned skill for whichever router or agent-UI library a ticket uses (React Router, TanStack Intent, CopilotKit's monorepo skills, Next.js only from 16.3), and Microsoft's `playwright-cli` for tests. **For a good-looking UI it means shadcn's skill as the component layer (Base UI, chat primitives, Trace and 21 AI Elements patterns), Impeccable for critique, Anthropic's Apache-2.0 `frontend-design` for new visual directions, Vercel's Web Interface Guidelines pinned as a review checklist, and a Google-spec `DESIGN.md` as the design-system artefact.** The glue is tools rather than skills: hey-api for the typed client, oasdiff, CopilotKit's aimock as a deterministic Gemini server, axe, and the react-hooks lint preset. No upstream source covers the ADK seam: ADK's API server is unauthenticated by design, `get_fast_api_app` has no end-user auth hook, ag-ui-adk reads the user from client input, ADK's session tables collide with application migrations, and Cloud Run and Firebase Hosting cut streams that ADK does not keep alive. That seam belongs in the toolkit as **one thin new `adk-fastapi-backend` skill plus new references in `adk-frontend-integration` and `deploy-adk-on-google-cloud`**; a first-party React or taste skill would only duplicate faster-moving upstream work. adk-system-designer needs one `companion_skills` field carrying install command, pin and load scope, beside the earlier `reference_patterns` field and an optional `design_system` pointer, because several companions do not pin themselves.

## Framework owners now ship the best companions inside their packages

The strongest guidance for both halves of the stack now ships with the libraries it describes. FastAPI has bundled an official skill at `fastapi/.agents/skills/fastapi/` since 0.133.1 (25 February 2026); its docs say the skill "stays aligned with the version of FastAPI installed in your project", and `uvx library-skills` installs it along with SQLModel's equivalent ([FastAPI tutorial](https://github.com/fastapi/fastapi/blob/master/docs/en/docs/tutorial/index.md)). Next.js retired `next-best-practices` in favour of version-matched docs in `node_modules/next/dist/docs/` and an `AGENTS.md` that `next dev` writes itself on 16.3+ ([next-skills README](https://github.com/vercel-labs/next-skills/blob/HEAD/README.md)). React Router moved its skill into the framework repo and makes `node_modules/react-router/docs/` the source of truth ([react-router skill](https://github.com/remix-run/react-router/blob/main/.agents/skills/react-router/SKILL.md)). TanStack Intent ships skills inside npm packages and writes an `intent-skills` block into `AGENTS.md` ([TanStack Intent](https://github.com/TanStack/intent)). CopilotKit's monorepo skill "carries almost no API detail on purpose" and sends the agent to regenerated docs ([copilotkit skill](https://github.com/CopilotKit/CopilotKit/blob/main/skills/copilotkit/SKILL.md)), and its `@copilotkit/react-core` package has carried skill references under `skills/react-core/` ([provider-setup.md](https://unpkg.com/@copilotkit/react-core@1.66.0/skills/react-core/references/provider-setup.md)).

Two consequences follow for tickets. **Package-shipped skills pin themselves through the lockfile but exist only after install**: Library Skills manages symlinks into `.venv`, so the full-stack template's committed `fastapi` and `sqlmodel` links dangle until `uv sync` has run ([library-skills skill](https://github.com/fastapi/full-stack-fastapi-template/blob/HEAD/.claude/skills/library-skills/SKILL.md)). **GitHub-hosted skills pin nothing.** Vercel's `metadata.json` still reads version 1.0.0, "January 2026" and "40+ rules" while the SKILL.md lists 70 ([metadata.json](https://github.com/vercel-labs/agent-skills/blob/HEAD/skills/react-best-practices/metadata.json)); `web-design-guidelines` fetches its rules from a mutable `main` URL at run time ([skill](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md)); shadcn's skill runs `npx shadcn@latest` when it loads ([shadcn skill](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md)). Tickets should therefore cite package skills by resolved package version and GitHub skills by commit.

### FastAPI's bundled skill replaces every third-party FastAPI skill

The official skill is concrete and current: `Annotated` dependencies with reusable aliases, return types over `response_model`, plain `def` "in case of doubt", `EventSourceResponse` for SSE, `app.frontend()` for built SPAs, native OpenTelemetry, uv/Ruff/ty, and "Do not use `ORJSONResponse` or `UJSONResponse`, they are deprecated" ([SKILL.md](https://github.com/fastapi/fastapi/blob/master/fastapi/.agents/skills/fastapi/SKILL.md)). It changes in the same PRs as the features; 0.142.3 (7 October) switched it to Asyncer for blocking code ([release notes](https://github.com/fastapi/fastapi/blob/master/docs/en/docs/release-notes.md)). The popular alternatives contradict it. wshobson's `fastapi-templates` (25,716 installs) still writes `= Depends(get_db)` defaults and `sessionmaker(..., class_=AsyncSession)` against unpinned requirements ([fastapi-templates](https://github.com/wshobson/agents/blob/main/plugins/api-scaffolding/skills/fastapi-templates/SKILL.md), [Skillselion](https://skillselion.com/skills/wshobson/agents/fastapi-templates)). Jeffallan's `fastapi-expert` imports `model_config` from pydantic, which is not an importable callable, and teaches `python-jose` and `passlib` where FastAPI's docs now teach PyJWT and pwdlib ([fastapi-expert](https://github.com/Jeffallan/claude-skills/blob/main/skills/fastapi-expert/SKILL.md), [FastAPI JWT tutorial](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)). Naming either would put contradictory guidance into adk-engineer's context. Trail of Bits' `modern-python` is sound uv/ruff/ty hygiene, but CC-BY-SA-4.0, so link it and never absorb it ([LICENSE](https://github.com/trailofbits/skills/blob/main/LICENSE)).

Because FastAPI releases almost daily (0.159.1 on 21 October), the toolkit should record the resolved version and gate features on it rather than track "latest" ([release notes](https://github.com/fastapi/fastapi/blob/master/docs/en/docs/release-notes.md)). **The gates that matter are SSE helpers from 0.135, `app.frontend()` from 0.138 with dependencies from 0.139, native OpenTelemetry from 0.142, and opt-in exporters from 0.143.** ADK 2.12 only requires `fastapi>=0.133` ([ADK pyproject](https://github.com/google/adk-python/blob/main/pyproject.toml)), so some ADK projects lack `EventSourceResponse`; those should use `sse-starlette`, which ag-ui-adk chose deliberately to hold its own floor at 0.115.2 ([ag-ui-adk pyproject](https://github.com/ag-ui-protocol/ag-ui/blob/main/integrations/adk-middleware/python/pyproject.toml)). SQLModel's bundled skill is correct but sync-only and silent on Alembic ([SQLModel skill](https://github.com/fastapi/sqlmodel/blob/main/sqlmodel/.agents/skills/sqlmodel/SKILL.md)), so name it only when a ticket chooses SQLModel for `def` routes; async SQLAlchemy 2 stays the default beside an async Runner. The official full-stack template is the best reference implementation and a poor dependency: it requires Python ≥3.14, uses sync SQLModel and password-JWT auth with the token in `localStorage`, and runs `fastapi run --workers 4` against FastAPI's own "one process per container" advice for clustered hosts such as Cloud Run ([Dockerfile](https://github.com/fastapi/full-stack-fastapi-template/blob/master/backend/Dockerfile), [FastAPI Docker docs](https://github.com/fastapi/fastapi/blob/master/docs/en/docs/deployment/docker.md#L451)).

### Vercel's React rules fit a Vite SPA once the server rules are scoped out

For a Python ADK backend the framework choice turns on whether a JavaScript server is needed at all. When a FastAPI app owns the JSON and SSE routes, **a Vite + React SPA with React Router v7 in data mode or TanStack Router, served by `app.frontend()` from the API's own origin**, is leanest, matches the toolkit's existing manual-browser recipe, and is endorsed by react.dev's note that its listed frameworks all ship as client-rendered SPAs ([react.dev](https://react.dev/learn/creating-a-react-app)). CopilotKit's documented ADK path is Next.js; on a Vite SPA "the runtime needs one of its own", a separate Node process to deploy and secure ([CopilotKit SPA docs](https://docs.copilotkit.ai/react-spa)). TanStack Start is still Beta on react.dev, so it is not a default.

`vercel-react-best-practices` is the strongest general engineering skill: 70 rules in eight impact-ranked categories, each an incorrect/correct pair, covering React 19.2's `<Activity>` and `useEffectEvent` and marking where React Compiler makes manual memoisation unnecessary ([SKILL.md](https://github.com/vercel-labs/agent-skills/blob/HEAD/skills/react-best-practices/SKILL.md)), with about 826K installs and three passing security audits on skills.sh ([skills.sh](https://skills.sh/vercel-labs/agent-skills/vercel-react-best-practices)). Its fit caveats belong in the ticket's `scope` line. About ten `server-` rules and the `next/dynamic` advice do not apply to a SPA, and its client fetching is taught through SWR ([client-swr-dedup](https://github.com/vercel-labs/agent-skills/blob/HEAD/skills/react-best-practices/rules/client-swr-dedup.md)), which conflicts with TanStack Query — the library hey-api generates options for and the full-stack template uses. A ticket that does not state TanStack Query invites the agent to introduce SWR.

Two toolkit pins have fallen behind this machinery. **The CopilotKit recipe's Next 15.5.24 gets none of Next's agent support**: `next-dev-loop` declares "Next.js 16.3+ with Turbopack" a hard floor and stops otherwise ([next-dev-loop](https://github.com/vercel/next.js/blob/canary/skills/next-dev-loop/SKILL.md)). **The manual-browser recipe on React 18.3.1 / Vite 6.4.3 is two Vite majors behind Vite 8** (12 March 2026), whose `@vitejs/plugin-react` v6 drops Babel and enables React Compiler through `@rolldown/plugin-babel` and `reactCompilerPreset` ([Vite 8](https://vite.dev/blog/announcing-vite8)). Both upgrades are explicit version decisions under the toolkit's no-silent-upgrade rule; record them as known gaps in `compatibility.md`. The React team publishes no consumer skill, and what it does publish is better absorbed as a gate: **React Compiler 1.0 (7 October 2025) and `eslint-plugin-react-hooks`, whose `recommended` preset now carries the compiler-derived rules** such as `purity`, `refs`, `set-state-in-effect` and `static-components` ([React Compiler 1.0](https://react.dev/blog/2025/10/07/react-compiler-1), [react-hooks README](https://github.com/react/react/blob/main/packages/eslint-plugin-react-hooks/README.md)).

On the CopilotKit route, name the monorepo's `copilotkit` (v3.2.0) and `copilotkit-cli`; the standalone `CopilotKit/skills` repo has moved and is frozen ([moved notice](https://github.com/CopilotKit/skills/blob/HEAD/README.md)). `copilotkit verify --round-trip --json` is a ready acceptance check whose "`UNKNOWN` … never means the check passed", and its blind spots — tool execution, event ordering, state sync — are exactly what the toolkit's `check_agui_trace.py` already covers ([copilotkit-cli](https://github.com/CopilotKit/CopilotKit/blob/main/skills/copilotkit-cli/SKILL.md)). **assistant-ui needs a correction to the earlier *Repos to integrate into ADK skills* report**, which said its `react-google-adk` package targets ADK JS only. Its setup skill now documents ADK Python backends and normalises their snake_case events ([google-adk reference](https://github.com/assistant-ui/skills/blob/HEAD/assistant-ui/skills/setup/references/google-adk.md)). The same reference's direct mode, `createAdkStream({ api, appName, userId: "user-1" })`, sends the user id from the browser and breaks the toolkit's session-ownership boundary, so a ticket citing assistant-ui must require its server route with `userId` derived from authentication, or a FastAPI gateway, and allow direct mode only in local demos. Its rule that edit and regenerate stay hidden without a server checkpoint (`getCheckpointId`) is worth absorbing. For tests, `playwright-cli` (Apache-2.0) is the default: it derives role-based locators from accessibility snapshots and documents request mocking and debug-attach ([playwright-cli](https://github.com/microsoft/playwright-cli/blob/HEAD/skills/playwright-cli/SKILL.md)), and Playwright MCP's own README tells coding agents that the CLI plus skills is more token-efficient ([playwright-mcp](https://github.com/microsoft/playwright-mcp/blob/HEAD/README.md)). Anthropic's `webapp-testing`, by contrast, calls `networkidle` waits "CRITICAL", and those never settle while an SSE stream is open ([webapp-testing](https://github.com/anthropics/skills/blob/HEAD/skills/webapp-testing/SKILL.md)).

### shadcn supplies the parts, Impeccable the judgement, DESIGN.md the system

shadcn/ui has become the component and token layer for agent UIs. Its official skill (`npx skills add shadcn/ui`, 271.1K installs) reads framework, Tailwind version and base library from `shadcn info --json` on every interaction and enforces concrete rules — semantic colours, "never raw values like `bg-blue-500`", `className` for layout only, `FieldGroup` forms, titled dialogs, `Empty` and `Skeleton` states ([shadcn skill](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md)). Base UI became the default primitive library on 2 July 2026, with Radix still supported, so tickets should record the base library from `components.json` ([Base UI changelog](https://github.com/shadcn-ui/ui/blob/main/apps/v4/content/docs/changelog/2026-07-base-ui-default.mdx)). Since June shadcn has added chat primitives and `typeset` for rendered markdown, and on 14 October `Trace`, `Code Block` and 21 copy-in AI Elements patterns (tool, confirmation, reasoning, sources, plan, checkpoint and more), each with a Markdown page an agent can read ([AI Elements changelog](https://github.com/shadcn-ui/ui/blob/main/apps/v4/content/docs/changelog/2026-10-ai-elements.mdx)). Its chat rules are the most implementation-ready agent-UI guidance found: one `TraceLine` per step with status words that agree ("Running, Ran, Failed to run"), approvals as a prompt outside the trace, and "**Map SDK states yourself; never pass one through**" — the toolkit's own application-owned-event rule restated for the UI ([rules/chat.md](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/rules/chat.md)). **Vercel's `vercel/ai-elements` will be deprecated at the end of November 2026 in favour of shadcn's AI Elements, so new work should not adopt it**; its skill also assumes Next.js, the AI SDK and Vercel's AI Gateway ([vercel/ai-elements](https://github.com/vercel/ai-elements)).

Impeccable (v4.7.0, Apache-2.0, 350.4K installs) is the critique companion. Its Operate mode, for "App UI, dashboards, editors, admin, settings, tools", ranks scanability above expression, demands seven states per interactive component and 150–250 ms transitions, and bans orchestrated page-load sequences ([operate.md](https://github.com/pbakaus/impeccable/blob/main/.claude/skills/impeccable/reference/operate.md)). Its critique pairs a deterministic detector with an isolated Nielsen-heuristic review and observes that "Most real interfaces score 20-32 out of 40" ([critique.md](https://github.com/pbakaus/impeccable/blob/main/.claude/skills/impeccable/reference/critique.md)); record those scores as evidence, not gates, and approve the detector binary it downloads on first run as an explicit setup step ([launcher](https://github.com/pbakaus/impeccable/blob/main/.claude/skills/impeccable/scripts/impeccable)). Anthropic's `frontend-design` (1.0M installs) is the best calibration against generic defaults, naming five clusters AI-generated design falls into, but its verification is a soft "taking screenshots to review if your environment supports it" ([SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)), so scope it to new visual directions and public pages. **Its licence is Apache-2.0; only Anthropic's docx, pdf, pptx and xlsx skills are proprietary** ([frontend-design LICENSE](https://github.com/anthropics/skills/blob/main/skills/frontend-design/LICENSE.txt), [docx LICENSE](https://github.com/anthropics/skills/blob/main/skills/docx/LICENSE.txt)). Vercel's Web Interface Guidelines carry the most checkable rules — no `outline-none` without a replacement, no `transition: all`, honour `prefers-reduced-motion`, `aria-live="polite"` for async updates ([command.md](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)) — but because the skill fetches them at run time, vendor a pinned copy under its MIT notice or cite the commit.

Two companions disagree on copy case: the guidelines want "Title Case for headings/buttons (Chicago style)", `frontend-design` wants sentence case, and left unresolved each will "fix" the other's output. **Decide per project in DESIGN.md's Do's and Don'ts**, together with the surface mode (Operate for the agent app, Persuade only for a landing page). DESIGN.md is the right home because Google's open spec (Apache-2.0, alpha, CLI 0.4.0) is now read by shadcn, Impeccable and Stitch, and its CLI lints contrast and broken token references, diffs versions, and exports a Tailwind v4 `@theme` block ([design.md](https://github.com/google-labs-code/design.md)); pin the CLI, since the spec is alpha. ui-ux-pro-max (408K installs) is the cautionary case: its product table recommends "Neutral + AI Purple (#6366F1)" and glassmorphism for AI and chatbot platforms ([products.csv](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/src/ui-ux-pro-max/data/products.csv)), precisely the convergent default Anthropic's design post set out to break ([Anthropic](https://claude.com/blog/improving-frontend-design-through-skills)).

### Tools, not skills, hold the contract and replace the model

No skill teaches the FastAPI-to-React contract end to end, but the tools are settled. FastAPI's docs recommend Hey API's `@hey-api/openapi-ts` and a stable `generate_unique_id_function` ([generate clients](https://fastapi.tiangolo.com/advanced/generate-clients/)); the template dumps `app.openapi()` offline, regenerates the client in a pre-commit hook and commits the generated folder ([generate-client.sh](https://github.com/fastapi/full-stack-fastapi-template/blob/HEAD/scripts/generate-client.sh), [pre-commit](https://github.com/fastapi/full-stack-fastapi-template/blob/HEAD/.pre-commit-config.yaml)). hey-api is at 0.99.0 while the template pins 0.97.3, so pin it exactly ([hey-api](https://github.com/hey-api/openapi-ts)). One deviation from the template is deliberate: it gitignores `openapi.json` ([.gitignore](https://github.com/fastapi/full-stack-fastapi-template/blob/HEAD/frontend/.gitignore)), but committing the spec gives oasdiff a reviewable base, and `oasdiff breaking main:openapi.json openapi.json --fail-on ERR` exits 1 on breaking changes ([oasdiff](https://github.com/oasdiff/oasdiff/blob/HEAD/docs/BREAKING-CHANGES.md)).

Streams are the weak spot. FastAPI documents SSE routes with an OpenAPI-3.2-style `itemSchema` inside a 3.1.0 document; hey-api generates a fetch-based `.sse` client that can send `Authorization`, POST bodies and `Last-Event-ID`, but its parsers cover only OpenAPI 2.0 to 3.1 and a grep finds no `itemSchema` handling, so the event payload is probably untyped ([serverSentEvents.ts](https://github.com/hey-api/openapi-ts/blob/HEAD/packages/openapi-ts/src/plugins/@hey-api/client-core/bundle/serverSentEvents.ts), [parsers](https://github.com/hey-api/openapi-ts/tree/HEAD/packages/shared/src/openApi)). Keep AG-UI streams out of the OpenAPI contract and type them with `@ag-ui/core`'s zod schemas, `verifyEvents` and the toolkit's trace checker ([core package](https://github.com/ag-ui-protocol/ag-ui/blob/HEAD/sdks/typescript/packages/core/package.json)); for an app-owned SSE stream, declare `AsyncIterable[PublicEvent]` over a discriminated union so the server validates, then validate again in the browser with zod.

For browser tests, **CopilotKit's aimock (MIT, v1.46.0) is the missing piece**: a real HTTP server that speaks Gemini REST and Vertex, records and replays, injects mid-stream disconnects and 429s, and exposes a request journal at `/__aimock/journal` ([aimock](https://github.com/CopilotKit/aimock/blob/HEAD/README.md)). The AG-UI dojo already points ADK agents at it through `GOOGLE_GEMINI_BASE_URL` and a fake key, drives Playwright journeys through ADK tool-confirmation interrupts, and compares each journey with a checked-in event-trace baseline ([dojo launcher](https://github.com/ag-ui-protocol/ag-ui/blob/HEAD/apps/dojo/scripts/run-dojo-everything.js), [e2e README](https://github.com/ag-ui-protocol/ag-ui/blob/HEAD/apps/dojo/e2e/README.md)). That preserves the toolkit's stance — real FastAPI, Runner, sessions and auth, only the model replaced — and lets "zero model calls on rejected auth" be proven end to end. Playwright's `route.fulfill` delivers a completed body and MSW's `sse()` covers only browser `EventSource` ([MSW](https://mswjs.io/docs/sse/)), so both suit component tests and neither proves streaming. Accessibility runs as `@axe-core/playwright` in the same specs, under Playwright's own warning that automated testing cannot detect all WCAG violations ([Playwright accessibility](https://playwright.dev/docs/accessibility-testing)).

## The toolkit needs one ticket field, one thin skill and new references

### One companion_skills list absorbs four competing field proposals

The research tracks proposed four overlapping additions to the ticket template — `companions:` with `design_system:` from the UI track, `companion_skills` from the FastAPI and React tracks, `external_skills:` with `references:` from the glue track, and the earlier report's `reference_patterns`. They collapse into three fields with one rule each. **`companion_skills` holds anything the implementing agent installs and loads**, package-bundled skills included, with install command, pin and load scope. **`reference_patterns` holds anything studied and then re-implemented ADK-natively**, which now covers scaffold repos such as the full-stack template and Google's deep-search recipe. **`design_system` points at the project's DESIGN.md.** `primary_skill` and `supporting_skills` stay first-party, and the new entries join, rather than replace, the process and protocol companions in the earlier report's table (`implement-spec`, `wizard`, `run-tck` and others).

```yaml
primary_skill: adk-frontend-integration
supporting_skills: [adk-fastapi-backend, adk-operational-guardrails]
companion_skills:          # installed and loaded; absence is missing setup, never evidence
  - name: fastapi
    source: library skill bundled in the fastapi wheel
    install: uv sync && uvx library-skills --claude
    pin: uv.lock (fastapi==<resolved>)
    load_when: any route, dependency, SSE or app.frontend() change
  - name: vercel-react-best-practices
    install: npx skills add vercel-labs/agent-skills --skill vercel-react-best-practices
    pin: vercel-labs/agent-skills@063bee94        # its metadata.json version is unreliable
    scope: async-, bundle-, client-, rerender-, rendering-, js- rules; skip server-; TanStack Query, not SWR
  - name: react-router
    install: npx skills add https://github.com/remix-run/react-router --skill react-router
    pin: remix-run/react-router@<sha>
    docs: node_modules/react-router/docs/         # version-matched by the lockfile
  - name: shadcn
    install: npx skills add shadcn/ui
    pin: shadcn-ui/ui@ba1503c; CLI shadcn@<exact> recorded in Evidence
    load_when: components, tokens, chat, Trace or AI Elements patterns
  - name: impeccable
    install: npx skills add pbakaus/impeccable
    pin: v4.7.0 (47d57da); detector binary download approved as setup
    load_when: critique, audit or polish after a UI change; Operate mode
  - name: playwright-cli
    install: playwright-cli install --skills
    pin: playwright-cli 0.1.22
    load_when: writing or debugging Playwright specs
design_system: docs/design/DESIGN.md      # copy case and surface mode live in Do's and Don'ts
reference_patterns:                        # studied, then implemented ADK-natively
  - id: RP1
    source: fastapi/full-stack-fastapi-template@<sha> scripts/generate-client.sh
    pattern: offline app.openapi() dump, hey-api client, drift diff in pre-commit
    adk_native: app imports without ADC; ADK routes kept out of the public contract
    drives: A1
    license: MIT; snippets with attribution
  - id: RP2
    source: google/adk-recipes@<sha> core/python/deep-search
    pattern: /run_sse parsing and HITL plan-approval timeline
    adk_native: through the authenticated gateway; no u_999, no allow_origins="*"
    drives: A3
    license: Apache-2.0; study only, no code copied
```

adk-engineer's run prompt gains one sentence — load the ticket's companion skills when installed, otherwise record them as missing setup and continue — which is the rule the designer's handoff already applies to specialists: "a missing skill is a setup prerequisite, not a claim that its guidance was applied" ([implementation-handoff.md](https://github.com/RuslanKhis/agentic-engineering-skills/blob/main/skills/adk-system-designer/references/implementation-handoff.md)). Evidence records the pin actually loaded. Precedence extends composition.md's existing division, in which "this toolkit's skill decides" ([composition.md](https://github.com/RuslanKhis/agentic-engineering-skills/blob/main/skills/adk-engineer/references/composition.md)): the toolkit wins on identity, ownership, security and the stream contract, a companion wins on library syntax for its pinned version, and DESIGN.md wins between UI companions. The designer's `check_schedule.py` does not validate skill names today, so extend it to require `name`, `install` and `pin` on every companion; until then a malformed entry passes silently.

### A thin adk-fastapi-backend skill fills the one real ownership gap

The tracks disagreed on whether to write a new skill. The FastAPI track proposed a small `adk-fastapi-backend`; the glue track proposed new references inside adk-frontend-integration and deploy-adk-on-google-cloud, with a sibling skill only if the frontend skill outgrew its entry point; the React and UI tracks advised against first-party React or taste skills. **The recommendation is to write the thin backend skill, put the browser-side and hosting additions into existing skills as references, and write no React or taste skill.**

The deciding fact is ownership. No current skill owns the non-agent HTTP surface — domain routes, application data and migrations beside ADK's tables, the public OpenAPI contract, identity verifier dependencies, the Cloud Run process shape, post-response work, rate limits and telemetry-exporter ownership. A grep of the toolkit finds no mention of Alembic, Cloud Tasks, `EventSourceResponse`, `app.frontend`, `x-goog-iap-jwt-assertion` or Firebase Hosting timeouts, and the designer's boundary-to-skill table has no HTTP-API row, so a migrations ticket today has no fitting primary skill. Google will not fill the gap either: every agents-cli template declares `frontend_type: "None"` ([templateconfig](https://github.com/google/agents-cli/blob/HEAD/src/google/agents/cli/scaffold/agents/adk/.template/templateconfig.yaml)). Folding all of it into adk-frontend-integration would turn a 75-line entry point, whose description excludes "ordinary React styling … non-ADK chat applications" ([SKILL.md](https://github.com/RuslanKhis/agentic-engineering-skills/blob/main/skills/adk-frontend-integration/SKILL.md)), into a general full-stack skill and blur its activation. A skill of 150–250 lines that defers idioms to FastAPI's bundled skill and the agent route to adk-frontend-integration keeps both triggers sharp. It would open with a version inspection that extends `inspect_project.py` into a FastAPI feature matrix, then make the topology decision (one app around `get_fast_api_app`, a gateway in front of a private ADK service, or an in-process Runner) with ADK's no-auth warning as the forcing rule. It would carry identity dependencies for IAP, Identity Platform/Firebase and self-issued PyJWT mapped to one principal, leaving the principle in adk-tool-auth-and-secrets, then application data and Alembic with ADK tables excluded, the public contract and its drift gate, the Cloud Run runtime shape and exporter ownership, with references for compatibility, identity, data and migrations, contract and testing, Cloud Run runtime and provenance. Its router row reads "HTTP API surface beyond the agent route → `adk-fastapi-backend`". Write forward and activation cases before claiming benefit; Microsoft's per-skill effectiveness experiments show the shape ([microsoft/skills scenarios](https://github.com/microsoft/skills/tree/main/tests/scenarios/fastapi-router-py)).

The alternative is sound if the author prefers to stay at 22 skills: place the same material as `contract-and-client.md`, `identity-providers.md` and `fullstack-scaffold.md` in adk-frontend-integration and `frontend-hosting.md` in the deploy skill, add an HTTP-API row mapping to adk-frontend-integration, widen its description, and re-run the activation corpus. A first-party React skill is not worth writing under either option, because it would duplicate Vercel's 70 rules and the framework-owned skills while drifting faster than they do. Nor is a taste skill: Impeccable and taste-skill both committed on 20–21 October, and `frontend-design` was rewritten in June and again in September 2026 ([commit history](https://github.com/anthropics/skills/commits/main/skills/frontend-design)), so a copy would be stale within weeks.

## Thirteen ADK and GCP defaults become explicit ticket rules

Several of the hazards below sit in Google's own samples and docs, which is why a ticket must state the rule rather than trust the reference. One reconciliation comes first. The earlier report recorded an ADK 2.12.0 changelog line that the user id "is taken only from an authenticated principal", yet the 2.12 `api_server.py` read for this report still documents its endpoints as unauthenticated and still carries `user_id` in the path and in `RunAgentRequest`'s body ([api_server.py](https://github.com/google/adk-python/blob/main/src/google/adk/cli/api_server.py)), and `get_fast_api_app`'s only auth hook is `trigger_auth_verifier`, for Pub/Sub and Eventarc routes ([fast_api.py](https://github.com/google/adk-python/blob/main/src/google/adk/cli/fast_api.py)). The scope of that fix was not traced, but it does not authenticate browser callers, so tickets treat these routes as open.

## What this research could not verify

Several version facts come from repository manifests and docs rather than registries, because `registry.npmjs.org` did not resolve and unpkg and jsDelivr were blocked. That leaves unconfirmed the current npm versions of React, Next, React Router, CopilotKit and assistant-ui; the `eslint-plugin-react-hooks` major that first put compiler rules into `recommended`; whether TanStack Query and Router already ship Intent skills, since the TanStack blog confirms only DB and tanstack.com lists the others as examples ([TanStack blog](https://tanstack.com/blog/from-docs-to-agents)); and whether axe supports a `wcag22aa` tag. ag-ui-adk 0.11.0 is what the repo's `pyproject.toml` showed on 22 October, not a PyPI check. library-skills.io and the Library Skills CLI source could not be fetched, so its behaviour for Gemini CLI targets or Windows symlinks is unverified. Install counts are partial: skills.sh search pages were blocked, so counts come from the leaderboard and the Skillselion mirror, and playwright-cli, CopilotKit, assistant-ui, Addy Osmani's skills and interface-design had none visible.

Much was read from source and never run. That includes hey-api's handling of FastAPI's SSE `itemSchema`, the template build, ag-ui-adk 0.11's identity binding through `dependencies=`, ADK 2.12's `url_prefix` effect on the OpenAPI schema and whether ADK routes can be excluded from it, aimock's coverage of ADK 2.12 request features and of Vertex or Enterprise mode, the event-to-UI-state mapping (an inference from shadcn's rules), and every acceptance check above. No ticket was trial-run through adk-engineer, and nothing measures whether FastAPI's skill improves output on ADK tasks.

Identity and hosting details are incomplete. The IAP signed-headers how-to gives the Cloud Run audience format, but the direct-IAP-on-Cloud-Run page did not restate header or audience, and its launch stage and support for external identities were not established ([IAP for Cloud Run](https://docs.cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run)); verify against a captured token before writing the recipe. Firebase's `check_revoked` latency and tenant-claim handling were not fetched. The Firebase Hosting 60 s limit is official, but the buffering evidence is a 2022 reply with no newer confirmation either way, and the `__session`-only cookie rule comes from a secondary blog. Firebase App Hosting, load-balancer idle timeouts for serverless NEGs and Cloud Run's official HTTP/2 streaming behaviour were not researched, and rate limiting keyed by verified principal on Memorystore or at the edge is a design inference without a primary source.

Finally, the companions were not tested together. `frontend-design`, Impeccable, taste-skill and shadcn can all trigger on "build a UI", and their overlap in one Claude Code session was not measured; the precedence rule and the DESIGN.md decisions should reduce conflict but have not been shown to remove it. The proposed fields and the new skill are untested against the toolkit's activation corpus.

## Conclusion

The centre of gravity has moved. In 2026 the authoritative FastAPI and React guidance is a package artefact that tracks the lockfile, so the toolkit's value no longer lies in teaching frameworks but in two things upstream will not supply: the ADK seam and the evidence discipline. Every hazard in the rules table sits between libraries that are each well documented on their own, and several sit in Google's own samples, which makes that seam the content worth owning. The companion field turns everything else into a supply-chain decision the designer records with pins, exactly as it already records model and ADK versions.

The most useful next step is empirical rather than editorial: one forward case that installs the recommended companions together and runs G04 and G07 through adk-engineer on a real agent with aimock, measuring trigger conflicts between companions and whether the official skills change the output. If the UI companions fight in practice, fix it through the DESIGN.md precedence rule, not with a first-party taste skill.
