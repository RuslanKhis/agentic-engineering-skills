## Versions and method

- macOS arm64; Node **24.15.0**; Skills CLI **1.5.24**; Gemini CLI **0.60.0**.
- The five Skills CLI runs began in disposable projects. All three agent IDs
  select `.agents/skills`, so this installer used canonical copies and needed no
  symlinks. A SHA-256 comparison covered every non-cache source file.
- Gemini CLI was installed into a temporary npm prefix with `--ignore-scripts`.
  Its bundled CLI ran the native management commands; optional keychain/PTY
  lifecycle builds and interactive operation were not exercised.
- Gemini's supported `GEMINI_CLI_HOME` setting isolated the test profile. Only
  the two owned test projects were marked `TRUST_FOLDER` in that profile; folder
  trust was not disabled. The actual user's settings and authentication were
  not changed. Installer `--consent` applied only to our reviewed local skill
  directory during the automated native-install check.
- Project discovery was tested before user skills were added. The final alias
  check then copied the collection into the isolated user `.agents/skills` and
  launched the list command from a separate empty project.

The native command forms exercised were:

```bash
gemini --version
gemini skills install --help
gemini skills list --help
gemini skills install /path/to/agentic-engineering-skills/skills --scope workspace --consent
gemini skills list
```

For ordinary user setup, leave off `--consent` and follow the installer's prompt.
Use the [setup guide](../integrations/google-coding-agents.md) for the GitHub
installation route and chat prompts.

## Observations retained

The first native test guard blocked all `fetch` calls, including Gemini's
embedded `data:` URL for its local WebAssembly component. That was a harness
error, not a network request or skill failure. The corrected guard allowed
local `data:` loading while blocking outbound HTTP/socket access.

With the corrected harness but an untrusted project, `gemini skills list`
returned exit code zero and no skills. The test checked names and locations,
not only the exit status. Trusting the two disposable projects in the isolated
profile exposed all twelve packages. The negative result is
[retained](artifacts/google-coding-agents/gemini-untrusted-results.json).

The Skills CLI runs attempted no network connections. Gemini's listing runs
attempted startup requests to `play.googleapis.com`; the guard blocked them.
No outbound request completed during these guarded checks. Package download
occurred separately before the checks. Gemini also reported its unavailable
ripgrep integration and used its grep fallback; this did not prevent discovery.

## Scope and limits

These results establish local package placement, file preservation and Gemini's
native skill discovery. They do not establish model activation, reference
loading during generation or the quality of code generated by Google clients.
No Google coding model, ADK provider or cloud deployment was invoked.
Antigravity's app, IDE and CLI were not launched or authenticated; their
invocation instructions were checked against [official documentation](../research/google-coding-agent-skills.md).

Global Antigravity placement was inspected in installer source, not installed.
Skills CLI 1.5.24 routes these shared agent targets to `~/.agents/skills` at user
scope, while Antigravity's product variants document different global roots.
The setup guide therefore recommends the verified project route and records
those differences. The prior [Claude/Codex generation results](updated-skills-laptop.md)
remain separate evidence.
