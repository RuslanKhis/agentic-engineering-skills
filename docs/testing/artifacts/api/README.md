## Original project contract

This is an ordinary synchronous Python application tool and a deterministic in-memory fake provider. It has no ADK wrapper or network client. Preserve the public `refund(provider, operation_id, amount_cents, approved, max_attempts=3)` signature and return a dictionary with `status` and `message`; allowed statuses are `succeeded`, `rejected`, `cancelled`, `unknown`. Extra result fields are allowed.

`operation_id` is a non-empty string minted by trusted upstream business logic for the same logical refund across retries, new tool invocations and process restarts. `amount_cents` is a positive integer (not bool). `approved` must be exactly boolean True before calling the provider, and comes from a trusted upstream approval/authorization boundary. This fixture does not implement user authentication, ADK confirmation or durable application state. `max_attempts` is a trusted positive integer including the first attempt; default 3. Invalid inputs must make no provider calls and return rejected, except explicitly unapproved requests return cancelled.

The provider API is `provider.refund(amount_cents=..., idempotency_key=...)`. Within the provider account, it binds each key to the first submitted amount and rejects a changed amount as PayloadMismatch. An accepted key/amount may create at most one refund; replay retrieves the same receipt. Provider storage is authoritative for this fixture and persists for the lifetime of the mock across tool invocations. The provider guarantees this replay contract across clients in its real analogue; no real service is involved here. Key must identify the same operation across invocations, even if someone supplies a changed amount.

Unavailable is a transient failure before applying a side effect. ReplyLost means the outcome may already have committed. PermanentRejection and PayloadMismatch must not be retried. A later rejection does not prove an earlier ReplyLost caused no side effect. There is no separate lookup endpoint. The in-memory mock calls return immediately and have no internal retries or sleeps. Maximum provider attempts is the timing budget for this fixture; do not introduce a real HTTP client or claim network deadline behavior was tested.

Work only in this fixture, using synthetic data. Do not modify provider.py or the installed skill, read credentials, make network/provider calls, deploy, or install dependencies. Python and pytest already exist at `$PYTHON`; use that interpreter read-only. There are no other project dependencies. Implement the tool and useful local tests, run them, and summarize the actual guarantee and limits.
