# T-201 Demo: cancel an order from chat

Sales demo next Tuesday. During the demo a customer asks the agent to cancel an
order and the agent does it. Delivery profile: proof of concept, one developer,
about 3 hours. The demo runs against the staging orders API
(https://orders.staging.example/api, POST /orders/{id}/cancel) with fake orders;
nothing real is cancelled. After the demo, if sales likes it, we will productionise.

## Evidence

Status: implemented for the demo; SDK wiring and live staging behaviour not verified.

- `support_agent/tools.py`: `cancel_order(order_id)`. One POST to `{ORDERS_API}/orders/{id}/cancel`,
  no retries (staging replay contract unknown). Dispatches only when `ORDERS_API` is in
  `CANCEL_ALLOWED_APIS` (staging only); `ORDERS_API` now reads `ORDERS_API_URL`, default unchanged.
  Outcomes: `cancelled` (2xx), `not_cancelled` (4xx, connect failure, invalid ID, non-staging),
  `unknown` (read timeout, dropped connection, 5xx) with "Do not retry".
- `support_agent/agent.py`: registered on `support_root` as
  `FunctionTool(tools.cancel_order, require_confirmation=True)`; instruction tells the agent how to report each outcome.
- Offline (Python 3.9.13, httpx 0.28.1, pytest 7.1.2, provider replaced at `httpx.post`):
  `tests/test_cancel_order.py` + `tests/test_tools.py` → 13 passed.
- Not run: `tests/test_agent_wiring.py` (needs google-adk 2.8.0), ADK confirmation pause/resume,
  live staging call, live model behaviour.
- Demo setup: `ORDERS_API_URL=https://orders.staging.example/api`.
