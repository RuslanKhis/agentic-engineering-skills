# T-201 Demo: cancel an order from chat

Sales demo next Tuesday. During the demo a customer asks the agent to cancel an
order and the agent does it. Delivery profile: proof of concept, one developer,
about 3 hours. The demo runs against the staging orders API
(https://orders.staging.example/api, POST /orders/{id}/cancel) with fake orders;
nothing real is cancelled. After the demo, if sales likes it, we will productionise.

## Evidence (2026-10-09)

Status: implemented for the proof of concept, verified offline only. The live demo flow and the ADK confirmation flow are **not run**.
Specialist: `safe-api-tool-calls`. Profile: proof of concept, taken from the ticket.

- `support_agent/tools.py`: `cancel_order(order_id)` sends POST `{CANCEL_ORDERS_API}/orders/{id}/cancel`. The base URL defaults to
  `https://orders.staging.example/api` (env `CANCEL_ORDERS_API`). It is kept separate from the production `ORDERS_API`.
  The order ID is validated before any request. The tool makes exactly one attempt, with no transport retries.
  Results: 2xx → `cancelled`. 4xx → `error` (not cancelled). Connect failure → `error`. Timeout, other transport error or 5xx → `unknown`,
  with a "do not retry" message.
- `support_agent/agent.py`: `root_agent` exposes the tool as `FunctionTool(cancel_order, require_confirmation=True)`, plus one instruction line.
- `support_agent/__init__.py`: `root_agent` is now imported lazily, so tool tests run without google-adk.
- Offline (Python 3.9.13, httpx 0.28.1, pytest 7.1.2, mock transport, sockets blocked):
  `python3 -m pytest -q -p no:cacheprovider tests/` → 19 passed, 1 skipped.
  The skipped test is `tests/test_agent_wiring.py`, which needs google-adk. That test is **not run**.
  The project requires Python ≥3.11, which had no httpx or pytest here; under 3.11 only a parse check was run.
- **Not run:** the ADK confirmation path (missing or rejected approval must cause zero POSTs), `adk web` with a live model, and the staging API itself.

Deliberately left out (production controls):
- Durable operation record / idempotency key and reconciliation of `unknown` outcomes. Trigger: productionise; needs the orders API replay/lookup contract.
- Authenticated principal and ownership check (can this customer cancel this order?). Trigger: productionise (`adk-tool-auth-and-secrets`).
- Re-check of the order state between approval and dispatch. Trigger: productionise.
- Spend stop for model calls: not built, because the demo route (`adk web` vs an owned Runner) is undecided and `RunConfig.max_llm_calls` is not inherited by `adk web`.
  For the demo, set a budget alert/quota on the API key's project. Trigger: before any non-demo use (`adk-operational-guardrails`).
