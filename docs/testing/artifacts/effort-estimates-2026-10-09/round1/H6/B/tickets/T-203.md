# T-203 Finish Gmail connections for the pilot

T-202 delivered the connection boundary and the read tool, tested offline
against doubles. Finish it so 30 pilot customers can connect Gmail for real.

- Google provider adapter: code exchange with PKCE, validate the ID token and
  take its `sub`, refresh with error classification (`invalid_grant` vs
  429/5xx/timeout/malformed), revoke. Include an access-token cache keyed by
  principal/account/client/scope/revision.
- Credential store on Secret Manager (or an encrypted DB column); shared
  connection index (Firestore/Cloud SQL) with revision compare-and-swap,
  because Cloud Run can run more than one instance.
- Gmail reader on `users.messages.list` + `get` (format=metadata).
- Gateway routes: start consent (authenticated, CSRF-protected), callback
  (HttpOnly Secure SameSite=Lax cookie binding; callback query strings
  kept out of logs), disconnect, status.
- Google Cloud console: OAuth client, consent screen, test users or
  verification submission (a person must do this). Testing mode limits
  the app to 100 test users and refresh tokens expire after 7 days. Check
  both facts against current Google documentation before relying on them.
- Bounded reconciliation for `pending_revocations`.

Acceptance: a real test account connects, the agent quotes its order
confirmation, a second account cannot see it, disconnect revokes at Google,
restart keeps connections, and a forced `invalid_grant` asks to reconnect.
