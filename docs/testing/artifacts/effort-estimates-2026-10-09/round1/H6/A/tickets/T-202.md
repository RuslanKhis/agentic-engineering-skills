# T-202 Customers connect their own Gmail

Pilot customers should be able to connect their own Gmail account so the
support agent can read their order-confirmation emails when they ask about an
order. Each customer connects only their own mailbox and can disconnect it.
The pilot starts with 30 customers in three weeks.

## Evidence (2026-10-09)

Specialist: `adk-tool-auth-and-secrets` (delegated OAuth, per-customer credential
ownership, disconnect). Profile assumed: pilot/MVP for 30 external customers.

Built (offline-verified with doubles for Google; no ADK, no network):
- `support_agent/gmail_oauth.py`: consent start/callback with random single-use
  10-minute state, PKCE S256, browser-binding cookie value, initiating-principal
  check, exact client/redirect check; granted-scope check (`gmail.readonly`);
  Google account `sub` bound to the connection; refresh token only in a vault
  (index keeps an opaque reference + revision); revision compare-and-set on
  connect/refresh/disconnect; `invalid_grant` -> `reauth_required` for that
  revision only; transient failures keep consent; disconnect is local first,
  then revoke + destroy, failures recorded in `pending_cleanup`.
- `support_agent/gmail_tool.py`: `read_order_confirmations(order_id, tool_context)`;
  mailbox owner from `tool_context.session.user_id`, never a model argument;
  query fixed to configured ACME senders + validated order ID; max 3 emails,
  2,000 chars each; resource 401 refreshes once without dropping consent.
- `support_agent/gmail_http.py`: httpx adapters for Google token/revoke/userinfo
  and Gmail list/get; errors carry no response bodies.
- `support_agent/agent.py`: tool added to `support_root` plus one instruction line.
- `support_agent/__init__.py`: `root_agent` now loaded lazily so tests run without ADK.

Checks run:
- `python3.11 -m unittest tests.test_gmail_connection tests.test_gmail_http`: 22 run, OK, 3 skipped (httpx absent on 3.11).
- `python3 -m pytest -q tests` (Python 3.9.13 + httpx, below the 3.11 floor; supplementary): 23 passed.
- `python3.11 -m py_compile support_agent/*.py`: OK.
- Skill inspector `--expect-adk 2.8.0`: exit 0, static pins match, no observations (`.adk-evidence/inspect_project.json`).

Not run / unverified: anything importing `google.adk` (agent construction, ADK
`tool_context` injection and the `session.user_id` accessor on 2.8.0, Runner
orchestration with a substituted model); real Google consent, refresh, revoke and
Gmail calls; multi-replica behaviour; restart with persistent stores.

Not built (pilot prerequisites):
1. Persistent `ConnectionIndex`/`ConsentStore` (e.g. Firestore with transactions)
   and a `TokenVault` (Secret Manager, one secret per customer, exact version);
   only in-memory stores exist. In-memory stores lose connections on restart and
   do not work across Cloud Run instances.
2. HTTP routes in the customer portal/gateway: `POST /gmail/connect` (CSRF-protected),
   `GET /oauth/gmail/callback` (sets/reads the Secure HttpOnly SameSite=Lax binding
   cookie; keep query strings out of access logs), `POST /gmail/disconnect`, and
   start-up `gmail_tool.configure(...)` with the OAuth client secret from Secret Manager.
3. Google Cloud OAuth client + consent screen. `gmail.readonly` is a restricted
   scope: an unverified external app in Testing mode is capped at 100 test users
   and its refresh tokens expire after 7 days (customers would reconnect weekly);
   production use needs Google verification and a security assessment.
4. A verified customer identity in the ADK session `user_id` (README describes an
   internal tool; there is no customer login in this repo).
5. Security review (T-104): customer email text is untrusted and now reaches the
   root agent, which also holds `send_email` and can transfer to refunds.

Controls deliberately left out at pilot depth: cross-replica cache invalidation
(the access-token cache is per process, but every use re-reads the connection
status from the index first, so a shared index blocks disconnected customers on
all instances; only a Gmail call already in flight completes), a reconciliation worker for `pending_cleanup`,
Gmail pagination beyond 3 results, Sensitive Data Protection on email text
(`protect-adk-sensitive-data`), audit logging of secret access. Trigger: before
moving beyond the 30-customer pilot.
