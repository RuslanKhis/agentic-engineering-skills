### Findings

1. **`deployment_metadata.json` points at the dev engine** (`claims-helper-dev/.../5823190446271381504`).
   `agents-cli deploy` updates the engine recorded there, so running it as-is would overwrite the
   dev engine and leave the pilot untouched. The pilot engine ID will only exist after the
   Terraform apply. Do not run `agents-cli deploy` until the file holds the pilot ID. Order:
   Terraform apply, repoint the file, deploy with `--update-only`. Keep the dev ID in
   `docs/` or the ownership journal; it is not ours to delete here.
2. **Role gaps.** Terraform grants no roles, and the CLI's set differs from the documented baseline.
   Decide whether to accept `aiplatform.user` for the pilot or grant `expressUser` instead, and
   add `roles/cloudtrace.agent` (via Terraform) so G04's traces arrive. Tools in `app/tools.py`
   were not checked for extra permission needs.
3. **No rollback.** `deploy` updates the engine in place. Pin each deploy to a tagged source
   version (`AGENT_VERSION`) and keep the last working source so redeploying it is the recovery.
   Needs git (or an archive) first, and a revision/rollback readback by Tomás.
4. **Terraform state** has no backend block, so it is local to this checkout. Losing it loses
   ownership of the engine. Questions in the next section.
