# Decision: what to spend the last holdout-sized budget on

Prepared 2026-10-27. No provider calls were made. Needs the owner's approval (Morgan Hale) before any run.

## Recommendation

Regenerate the five holdout predictions on v14 (one run, writer and review, ~$3.10-3.40) and hand that in as the deliverable. Do not spend it on re-running the development cases.

Why:

1. **The handed-in deliverable does not come from the version the report describes.** `deliverables/holdout-predictions.json` was generated by v9 (code `5d20b7e`, writer-v9, k=2). v14 differs by five changes (ADRs 0010-0014: prompt rule, k=4, a waiver check, a prompt worked example, a repair loop). None of them has been run on a holdout case. The report would present v14 next to v9 outputs.
2. **The development 5/5 is not evidence of generalisation.** Each fix was written from one development case and verified by re-running only that case (every ADR says "Other development cases not re-run (cost)"). ADR 0013's worked example was written from PA-2026-0201 and then checked on PA-2026-0201. At v9 the set scored 3 of 5. The 5/5 combines five different versions, each case last run on a different one, and no single version has been run on all five. So it measures how well the fixes fit the cases they were made from, and it cannot show that an earlier fix survived a later change. A dev re-run on v14 would cost about the same (~$3.3, like `dev-v9-all`). It would check regressions but still could not say anything about unseen cases.
3. **The holdout is the only unseen data, and v9 was its only use.** The reservation `holdout-deliverable` was set up for exactly this run, and the campaign scope says "holdout predictions regenerated once with the final version".

Limits of what the run shows: five cases, temperature 1.0, one sample per case. A v9-vs-v14 difference of one or two decisions is within noise and must not be reported as an improvement or a regression. It shows whether v14 produces valid, sensible outputs on unseen cases and replaces the stale deliverable. It scores only if holdout labels are available (see question 2).
