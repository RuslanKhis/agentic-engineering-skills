# G03 Customers see only their own revenue in the portal

## Outcome

A signed-in customer asks the portal agent about their revenue with Fernhill and only ever gets
their own account's figures; nothing the agent does can change data in the warehouse.

## Acceptance

- [ ] A1 WHEN a customer asks for their monthly revenue THE agent SHALL answer from their own account only (C1)
- [ ] A2 IF a message names another customer's account ID THEN THE agent SHALL NOT return that account's figures (C1)
- [ ] A3 IF any statement other than a read reaches the warehouse THEN it SHALL be refused by the database layer (C2)

Verification, automated: `python -m unittest discover -s tests -t .` exits 0 (Toolbox double; the
live Toolbox server is not available in development).

## Evidence

Status: implemented; **tests not run in the authoring session (no shell available)**. Offline
tier only; no live Toolbox, BigQuery or IAP evidence. Boxes above stay unticked until the command
above has exited 0 and the live checks below have run.

C1 enforcement (customer scope):
- `portal/identity.py` now verifies the IAP assertion (signature, expiry, audience via
  `google.oauth2.id_token.verify_token`, plus issuer and `email` checks) and fails closed; it used
  to base64-decode an unverified token. Needs `IAP_AUDIENCE` set in the portal's environment.
- `analytics/portal_agent.py` builds one agent per request with `bound_params={"tenant_id": <id from
  the verified identity>}`; the model no longer reads the ID from the message and cannot pass it.
  A `before_tool_callback` (`portal/tenant.py`) refuses any tool outside `customer-revenue` and any
  call carrying `tenant_id`.
- Decision: `toolbox-adk` is pinned at 0.5.2 and pins must not change in a feature change, so the
  Toolbox `secure: true` parameter (toolbox-adk >= 1.4.0, per the skill's notes) is not used. Moving to
  it is a separate pin-change ticket; it would let the server itself refuse a model-supplied ID.
- Recheck at the effect: the SQL filters `customer_id = @tenant_id` (driver-bound).

C2 enforcement (read-only at the database end):
- `tools.yaml`: source `readOnly: true` (Toolbox dry-runs and rejects non-SELECT), `allowedDatasets:
  [sales]`; the free-form `bigquery-execute-sql` tool is removed from tools and toolset; the `table`
  template parameter is limited by `allowedValues` to `invoices_summary` and `credit_summary`.
- The toolbox identity `portal-toolbox@...` must hold only Job User and Data Viewer on `sales`
  (IAM, not changed here).

Not verified / open:

  package not installed here).
- IAM review of `portal-toolbox` roles; `IAP_AUDIENCE` value.
- `tools.yaml` SQL text is unchanged, but finance should confirm the template given the
