# G01 A handler sees a draft type and urgency for a new home claim

## Outcome

A handler sees a draft type and urgency for a new home claim, built from a de-identified
notification (D1: a draft a person accepts, never an automated decision). Implements C4.
Model pinned as `gemini-3.5-flash-001` (D2). Cover position is G02, not here.

## Scope

- In: notification parsing, SDP de-identification in `app/deidentify.py` before the model call,
  draft schema, `app/agent.py` LlmAgent with an output schema (module paths proposed; no
  repository exists yet).
- Out: cover position and clause citation (G02); handler queue (G03); spend stop (G04).
- Depth: pilot depth; floor kept (no secrets in code, pinned model, a person accepts every
  draft). SB05 is deferred to production.

## Constraints

Stack and pins as in the design (D2, D5): Python 3.12, google-adk 2.12.0, Vertex AI in
europe-west2, project `fm-claims-pilot`. When de-identification fails the draft is withheld (C4).

## Acceptance

- [ ] A1 WHEN a notification arrives THE app SHALL return a draft with type and urgency (C4)
- [ ] A2 IF a note contains a name, phone or email THEN THE model request SHALL NOT contain it (C4)
- [ ] A3 (floor) THE agent SHALL use the pinned model ID `gemini-3.5-flash-001` and hold no secret in code

Verification, automated: `python -m unittest tests.test_draft` exits 0, with a recorded model
double; offline. The canary test for A2 inspects the request sent to the model double.
