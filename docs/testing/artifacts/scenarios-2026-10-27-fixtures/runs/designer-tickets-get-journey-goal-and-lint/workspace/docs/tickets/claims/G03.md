# G03 A handler sees only their team's claims in the queue

## Outcome

A handler opens the queue view and sees only their team's claims; another team's claim returns
404. Implements C1 with identity from IAP. Rulings this ticket takes: the react-router pin is
"to be chosen" in the plan, so this ticket chooses and records it in AGENTS.md.

## Scope

- In: FastAPI dependency that derives the handler's team from the verified IAP identity and
  filters the queue; `/api` routes (SB01); React SPA with two routes (queue, claim) using
  shadcn at the pinned version; the Companion table written into AGENTS.md; Cloud SQL create
  and delete scripts; the tool-hop team recheck helper that later tools call.
- Out: claim history and spend stop (G04); cover position (G02); any write to claims.
- Depth: pilot depth; floor kept. SB05 deferred to production.

## Constraints

Identity comes from IAP only, never a client-supplied team. Stack per D5 and the design.
UI follows docs/design/DESIGN.md.

## Resources created

Cloud SQL for PostgreSQL `fm-claims-pilot-sql` (db-custom-1-3840, 10 GB SSD, europe-west2, no
HA); idle cost about £1.60 per day (pricing page read 2026-10-05,
https://cloud.google.com/sql/pricing); cleanup
`deploy/delete_sql.sh --project fm-claims-pilot --instance fm-claims-pilot-sql`; absence
verified with `gcloud sql instances list --project fm-claims-pilot`; owned by the cost
contract (Later, "Decommission" row). Write and test `deploy/delete_sql.sh` here beside
`deploy/create_sql.sh`. Creating the instance is a paid cloud action: do it only after explicit
authorisation; local tests use a local PostgreSQL or an in-memory double.

## Acceptance

- [ ] A1 WHEN a handler opens the queue THE app SHALL list only their team's claims (C1)
- [ ] A2 IF a handler requests another team's claim THEN THE app SHALL return 404 (C1, SB01)

Verification, automated: `python -m unittest tests.test_queue` exits 0; offline with a stub
IAP identity. Verification, manual: none.
