# Generated workflow: test evidence

This is a snapshot produced by the Codex CLI smoke test, not a production application.
`workflow.py` and `test_workflow.py` were generated by the coding session.
`test_acceptance.py` was written independently before generation and kept outside
that session's project. `before_workflow.py` is the original unimplemented seam.
`prompt.txt` preserves the submitted request.

## Input contract

Implement `build_workflow(policy_lookup, glossary_lookup) -> BaseAgent` for a
Google ADK document-review application. Both injected asynchronous functions
receive the current document text and return strings. Run them concurrently,
then store `policy_evidence`, `glossary_evidence` and `review_result` with exact
`policy` and `glossary` values. The final response includes both outputs.
A failed lookup must not publish a successful review, and separate sessions
must have independent results. Use synthetic local lookups through an actual
ADK Runner; no model call or hosted service is needed.

## Repeat the code checks

Use a Python interpreter containing the recorded versions: Python 3.11.4,
`google-adk==2.8.0`, `google-genai==2.19.0`, `pytest==8.4.2` and
`pytest-asyncio==1.4.0`. Set `PYTHON` to that interpreter, then run from this directory:

```bash
PYTHONPATH=. PYTHONDONTWRITEBYTECODE=1 "$PYTHON" -m pytest -q -p no:cacheprovider test_workflow.py test_acceptance.py
```

The generated tests reject network connections, Google authentication and GenAI
client construction. These checks exercise injected lookups and in-memory ADK
sessions. They do not establish production persistence or provider integration.
The [CLI report](../../codex-cli-smoke.md) distinguishes fresh code generation
from rerunning this snapshot.
