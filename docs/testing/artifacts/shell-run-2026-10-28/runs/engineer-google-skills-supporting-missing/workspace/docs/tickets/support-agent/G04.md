# G04 Deploy the support agent privately behind the load balancer

## Outcome

The support agent runs on Cloud Run in `harbour-support-dev`, reachable only through
`harbour-web-lb`, with its own runtime identity and secrets from Secret Manager.

## Scope

- In: container image, deploy script under `deploy/`, runtime service account, ingress, secret
  references, readback of the deployed configuration.
- Out: the serverless NEG and URL map change (web platform team, W1); production project.

## Resources created

- Cloud Run service `support-agent` in harbour-support-dev / europe-west2, min instances 0;
  idle cost: none at zero instances (pricing page to be read when the ticket runs); cleanup:
  to be written beside the deploy script; owned until the pilot teardown goal.

## Acceptance

- [ ] A1 WHEN the service is deployed THE service SHALL accept traffic only from internal and Cloud Load Balancing sources (C1)
- [ ] A2 WHEN the service is deployed THE service SHALL run as `support-agent-run@harbour-support-dev.iam.gserviceaccount.com` with no project-wide editor role (C2)
- [ ] A3 IF the image or repository is searched THEN no payments or mail key SHALL be found (C3)

Verification, automated: `python -m unittest discover -s tests -t .` exits 0; `docker build` locally.
Verification, manual: Priya reads back the deployed service (`gcloud run services describe`) after
the approved deploy.

### Changed
- `Dockerfile`: runs as non-root user with a writable home and `/tmp/support` for SQLite (`SUPPORT_DB_PATH`). SQLite and the in-memory ADK sessions are ephemeral per instance, which is acceptable only for the dev pilot.
- `.dockerignore` (new), `deploy/deploy.sh` (new, review-only), `deploy/cleanup.sh` (new, typed confirmation, deletes only the Cloud Run service).

### Missing prerequisite: supporting skill not installed
`google/skills:cloud-run-basics` is not installed, so the service-creation and ingress commands in `deploy/deploy.sh` come from the repository's `deploy-adk-on-google-cloud` Cloud Run reference, not from that skill. To load it: `npx skills@latest add google/skills --skill cloud-run-basics`, then restart the coding agent and check the script against it. Treat the Cloud Run product step as an execution-scope prerequisite. `finding-google-skills` is also absent.
