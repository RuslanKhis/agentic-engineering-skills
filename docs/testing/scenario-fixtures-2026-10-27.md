# Scenario fixtures and the first broad scenario run · 27 October 2026

Before this phase 126 of the 152 scenarios in `evals/scenarios.json` were
`fixture-missing`: their context described a project that did not exist, so
[the runner](runner-and-graders-2026-10-27.md) refused to run them, and no
scenario whose primary is `adk-engineer` or `safe-api-tool-calls` could run.
This records the fixtures built for them, the blindness checks, a run of 77
scenarios and the triage of every failed assertion.

## What was built

**Runner.** [`scripts/run_scenarios.py`](../../scripts/run_scenarios.py) now
composes a workspace from shared bases under `evals/fixtures/base/<name>/`,
explicit copies and the scenario's own overlay under `evals/fixtures/<id>/`
(later layers replace files of earlier ones), then applies listed removals.
Old copy-only entries are unchanged. New in `evals/scenario-fixtures.json`:
`base`, `overlay`, `remove`, `tests` (`pass` or `fail`: the composed
workspace's own unittest suite) and the status `not-representable` with a
`reason`. Three fixes came out of the runs: the judge's cost is recorded per
scenario; a prompt that starts with `/<skill>` counts as loading that skill
(Claude Code expands it before the first turn and the stream does not echo it,
so ticket runs had reported their primary as not loaded); and a file longer
than the evidence limit keeps its head and tail instead of only its head (a
35 KB plan lost its Later table to the judge).

**Six base projects**, each believable and small, none naming its own defects:

| Base | What it is | Used by |
| --- | --- | --- |
| `support-assistant` | ADK 2.12 support and refund assistant: tools without ADK imports, payments and mail clients behind a transport seam, SQLite store, IAP principal, FastAPI app, 11 offline tests | 44 scenarios |
| `support-plan` | Design (C1-C5, SB rules, decisions), plan with schedule block and five tickets for a reply-language PoC; passes `plan_status.py` and `check_tickets.py` | 9 |
| `doc-pipeline` | Planning-decision pipeline (source, writer, review, export) with a counted OpenAI-compatible transport, scripted double, checkpoint store with a 1 MiB limit, campaign ledger, retained runs | 12 |
| `claims-docs` | Claims-triage discovery brief, design, pilot plan with waits, Later list and a charged resource | 5 |
| `support-web` | Pinned Vite React chat under `web/` and a DESIGN.md | 5 |
| `sql-agent` | Revenue analytics agent: router, reviewed templates, schema collector, SQL author, capped executor | 4 |

**Fixtures** for 115 scenarios (112 with their own overlay), each with a judge-only
`evals/graders/<id>/situation.md` that says what the fixture holds, where, and
which assertion each part serves. Where a scenario's context needs a real
installed SDK, the fixture states that google-adk is not installed and the
assertion is graded on whether the agent reports the SDK tier as not run.

**Not representable (11)**, each with its reason in the fixture file: the
three field-note scenarios and `engineer-notices-mixed-skill-versions` (a
shell, a home directory outside the workspace, an SDK that raises at run time,
or a user-level install of an older skill version), five practice-profile and
discovery scenarios and `designer-offers-org-defaults-from-practice-profile`
(the profile lives under `AGENTIC_ENGINEERING_HOME`, which the confined agent
cannot read), and `maintainer-triage-treats-issue-text-as-data` (needs the full
checkout and a shell).

**Runnable:** 26 before (21 empty-workspace, 5 repository fixtures), 141 now
(23 and 118); none is `fixture-missing`
([runnable-list.md](artifacts/scenarios-2026-10-27-fixtures/runnable-list.md)).

## Blindness

- **Contexts.** 33 contexts read as fixture-building instructions ("Supply
  ...") or listed the defects the agent was meant to find; each was rewritten
  in the voice of the person asking, keeping every constraint the assertions
  rely on, with the original kept in the scenario's `situation.md`. One more
  (`engineer-resumes-from-progress-block`) changed after triage, below. Before
  and after:
  [context-rewrites.json](artifacts/scenarios-2026-10-27-fixtures/context-rewrites.json).
  Prompts and assertions are unchanged except one factual correction (below).
- **Own packs.** `evaluation-selected-source-support` used the evaluation
  skill's worked example, which the agent could read in the installed skill
  next to its calibration notes; it now has a 17-case community-hall pack and
  judge-only labels. `memory-ingestion-scan-detection` used the memory skill's
  demonstration PDFs, whose generator ships with the skill; it now has its own
  four-page pack, generated by `evals/graders/memory-ingestion-scan-detection/make_pack.py`
  (grader material), and the test checks the committed pack and inventory
  against it. `evaluation-preinference-contract-qualification` gets its own
  source pack, so the skill asset's `fixture_meanings` no longer double as its
  answers; its reviewed references and invalid controls are grader material.
- **Checks.** [`tests/test_scenario_fixtures.py`](../../tests/test_scenario_fixtures.py)
  fails when a base or overlay file carries a planted-defect marker ("planted",
  `# BUG`, "grader", `evals/`, "answer key", "deliberately broken" and similar),
  copies a grader, trial or skill file, or shares a grader file's name; when a
  runnable context names grader material or starts with builder instructions;
  when an overlay is not listed or a base is unused; and it builds every entry
  that declares `tests` and runs its suite offline with the standard library.
  Two existing copies from skill assets stay allow-listed with a reason
  (`document-coverage.json`, `retrieval-gold.json`: inputs the user names, not
  answers). `tests/test_grader_material.py` allows one unlisted grader file,
  the old source-support labels, which the evaluation skill's own unit test
  reads.

## Runs

**Method.** `run_scenarios.py run`, agent and judge `claude-sonnet-5-5`
through `claude-cli` (Claude Code 2.1.306), three judge repeats with majority
verdicts, `--max-turns 30`, 900-second timeout, `--max-budget-usd 3`, default
confinement (Read, Write, Edit, Glob, Grep, Skill; no shell), project skill
install. Batches of six to nine scenarios ran in parallel. A usage limit
stopped 9 agents and the judging of 22 scenarios part-way; finished agents were re-judged on
their unchanged evidence and one cut agent was re-run. Three scenarios were
re-judged after a runner or assertion fix. Evidence per scenario (task, agent
record, final answer, judge replies, files written) and every batch's results
are under
[artifacts/scenarios-2026-10-27-fixtures](artifacts/scenarios-2026-10-27-fixtures/);
the per-scenario table with every vote is
[summary.md](artifacts/scenarios-2026-10-27-fixtures/summary.md).

**Spend.** $39.17 in all: agent $28.77 and judge $9.69 for the recorded
results, plus $0.71 of judge calls superseded by re-judging. The cap was $40,
so after the evaluation batch only one more batch of eight (one scenario per
remaining skill) was started. 77 scenarios were graded (74 of them newly
runnable, 3 the rebuilt blind packs).

## Triage

Every assertion that failed by majority, and every pass with split votes, was
classified against the evidence, the fixture and the installed skill text; the
five tables (180 rows) with file and line quotes are under
[triage/](artifacts/scenarios-2026-10-27-fixtures/triage/).

| Class | Rows |
| --- | --- |
| (a) skill defect | 29 |
| (b) fixture or assertion defect | 42 |
| (c) run variance: the skill covers it, often in a reference the agent opened, and the answer left it out; or split votes | 109 |

The largest pattern is not a single skill: plain-language prompts that did
not name a skill often started with `Glob **/*` and went straight to the code
without loading any skill (12 of 77 runs did not load their primary), and in
most (c) rows the agent read the right reference and still omitted the point.

## Limits

One run per scenario: the phase 7 record showed agent run-to-run variation
larger than the judge's, so a single run per scenario says which assertions
fail now, not how often. 39 of 333 assertions had split judge votes. The
agent had no shell, so this measures what the skills lead an agent to write
and claim, not what it verifies. Fixtures were written by agents of the same
model family that ran them; each overlay was validated (composition, offline
suite, blindness patterns) and self-reviewed against its context, and the
triage found the defects listed above, but others may remain.

## Checks

`.venv/bin/python scripts/check_repo.py` passed on Python 3.12.9 with the new
fixture tests (every declared fixture suite runs offline with the standard
library) and the runner tests for composition, removal, not-representable
entries, judge cost, slash-command loading and evidence clipping.
