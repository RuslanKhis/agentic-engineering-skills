# memory-ingestion-scan-detection: what the pack holds

The pack in `pack/` was generated by `make_pack.py` beside this file; it is
this scenario's own pack, not the memory skill's demonstration fixture.
`inventory.json` records what each page carries and the route a correct
qualification takes.

| File | What it is | Serves |
| --- | --- | --- |
| `pack/01-design-code-dc7.pdf` | Text page: policy DC7, about 890 characters in the text layer | control (text route) |
| `pack/02-local-plan-p12.pdf` | Scanned page: one embedded greyscale image as the body; text layer is only the running header "Example Borough Local Plan 2019 - page 12" | A1 (low density, OCR or vision route), A5 |
| `pack/03-cycle-parking-table.pdf` | Table C1 drawn with vector rules (12 rule operations), five rows plus note b | A2 (table flagged, text and image) |
| `pack/04-rear-elevation.pdf` | Rear elevation drawing, 16 vector operations, written dimension "3.2 m to eaves", scale statement "Scale 1:100 @ A3", scale bar 0-4 m | A2 (drawing flagged), A3 (dimension and scale as separate fields; any pixel-derived value is an estimate) |

A4: an image budget sized from this pack is three or four page images
(scan, table, drawing; the text page needs none), with the thresholds named
as defaults to calibrate.

A5: no OCR engine or vision model is available; the scanned page (and the
visual check of the table and drawing) stays unresolved, not empty.

Original context, before the rewrite: "Use the memory skill's ingestion
fixture, copied to pack/ (the generator's own inventory is held back for
grading): a text page, a header-only scanned page with an embedded image, a
table page and a drawing page with a scale bar and a written dimension. No
OCR engine or vision model is available in this trial."
