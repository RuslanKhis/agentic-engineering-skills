# G02 Streamed replies

## Outcome

Replies appear in the chat as they are generated, and every stream ends in a known state (D2).

## Scope

- In: an SSE route `POST /api/chat/stream` in `app/stream.py` that relays ADK partial events and
  ends with one terminal event (`completed`, `failed` or `interrupted`); the chat panel reading it
  with fetch.
- Out: failure display (G03).
- Depth: proof of concept.

## Resources created

none

## Acceptance

- [x] A1 WHEN the run finishes THE stream SHALL end with a `completed` event after the text (C3)
- [ ] A2 IF the run raises after partial text THEN THE stream SHALL end with `failed` and no `completed` (C3)
- [ ] A3 IF the client disconnects THEN THE server SHALL stop the run and record `interrupted` (C3)

Verification, automated: `python -m unittest tests.test_stream` exits 0, offline (scripted event
source; Runner-level test written and reported as not run without the SDK).
Verification, manual: none.
