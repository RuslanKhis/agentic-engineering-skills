# G03 Sessions on Cloud SQL

## Outcome

Conversations survive an instance restart: the FastAPI app uses
`DatabaseSessionService` on a Cloud SQL for PostgreSQL instance instead of
`InMemorySessionService` (D1, D2).

## Scope

- In: a script under `deploy/` that creates the instance, database and user in
  `harbour-support-dev`; the session service URL from settings; the Cloud Run
  service connected to the instance.
- Out: migrations of application tables; any other project.

## Resources created

- Cloud SQL for PostgreSQL 16 instance `support-sessions-dev`, `db-custom-1-3840`,
  10 GB SSD, private IP, `europe-west2`, project `harbour-support-dev`; idle cost
  about USD 1.75 per day (pricing page https://cloud.google.com/sql/pricing, read
  2026-10-20); cleanup command: to be written in this ticket; absence verified by
  `gcloud sql instances list --project harbour-support-dev`; lifetime owned by
  [G06 Pilot teardown](G06.md).

## Acceptance

- [ ] A1 WHEN the instance restarts THE conversation SHALL continue with its earlier turns (C2)
- [ ] A2 IF the database is unreachable THEN THE chat route SHALL return 503 and no partial session (C2)

Verification, automated: `python -m unittest tests.test_sessions` exits 0 offline
(SQLite URL); the live check against Cloud SQL runs after the instance exists.
Verification, manual: none.

Execution scope: creating the instance in `harbour-support-dev` is authorised
(Priya, 2026-10-24). Nothing else in the cloud is.
